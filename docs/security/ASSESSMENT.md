# ComplyLet security assessment

24 November 2026 · Phase 1 foundation

## Scope and conclusion

Reviewed the implemented React UI and proxy, Spring MVC and OIDC security chain, browser session lifecycle, workspace authorisation, Flyway policies and grants, Compose and Keycloak configuration, dependency manifests and GitHub Actions against AGENTS.md and the master specification. Runtime verification uses synthetic identities and a disposable loopback stack. Findings below distinguish implementation defects from missing release controls. Phase 2 stays closed. The current product has no production deployment configuration.

## Prioritised findings

| ID and severity | Affected components and business impact | Remediation and verification requirements |
|---|---|---|
| S01 · High · Partially mitigated | Local Java, CI and Keycloak. The verification host’s Java 21.0.9 predates current security baselines. CVE-2026-114938 warrants runtime review, especially for affected x86-64 JVMs. A compromised process could expose sessions and database access. | Set the vendor’s interim JVM mitigation for CI and development Keycloak. Install a supported patched JDK such as Temurin 21.0.13.1+2 or a later patched build and inspect the actual JVM build and architecture in CI and every deployed image. Run the full suite on those builds. Container JVM and image scan remain pending. [Adoptium guidance](https://adoptium.net/zh-CN/news/2026/11/temurin-november-2026-cspu-java4shell), [Keycloak guidance](https://www.keycloak.org/2026/11/java4shell-vulnerability-cve-2026-114938), [Oracle Java advisory](https://www.oracle.com/security-alerts/cspunov2026.html). |
| S02 · High · Open release blocker | OIDC and BFF sessions. In-memory, instance-local revocation invalidates application access on subsequent requests. A live provider SSO session may still mint fresh application access. Enforced MFA, step-up, rate limits and anomaly detection are pending. Account compromise could affect every workspace the account can open. | Select a production provider and shared revocable store. Require enforced MFA and recent step-up before adding privileged writes. Verify provider termination, multi-instance revocation, token and session lifetimes, enrolment and recovery, throttling and incident alerts using the production topology. Verify that deactivation and role changes affect subsequent requests and that concurrent changes preserve ownership safeguards. |
| S03 · High · Open release blocker | Deployment and runtime configuration. Production TLS, HSTS at the frontend edge, network controls, credential rotation, encryption and backup evidence are absent. Local fixtures use loopback HTTP and development credentials. An unsafe deployment could expose sessions or customer data. | Provision an approved private deployment with managed secrets, separate database identities, secure cookies, encrypted storage and backups, least-privilege networking and restore exercises. Inspect browser-facing headers at the real ingress and verify ports and secrets across environments. |
| S10 · Medium · Remediated in code | Embedded Tomcat 11.0.27 was in vendor affected ranges for denial of service and configuration-dependent access and cache-control issues. No affected optional feature was established as reachable on the local application. | Override the Boot-managed Tomcat family to 11.0.29 and verify the versions in the packaged JAR and the local browser suite. Continue reviewing Tomcat advisories and avoid enabling clustering without independent review. [Apache Tomcat security advisories](https://tomcat.apache.org/security-11.html). |
| S04 · Medium · Remediated in code | PostgreSQL membership and organisation RLS. Before V2, a multi-workspace actor could see their other memberships from SQL after the transaction bound one workspace. This weakened defence in depth if a repository query omitted its tenant predicate. The existing selection service explicitly checks the requested workspace. | Flyway V2 narrows policy visibility when bound and preserves unbound actor discovery. Verify both tenants remain discoverable before binding, only the bound tenant is visible through the runtime role and transaction settings clear after commit and rollback. |
| S05 · Medium · Remediated in code | Spring Security. A namespace-wide authenticated grant could admit a future API controller without an explicit route decision. Optional OpenAPI also accepted unverified authenticated identities. These conditions increase the likelihood of unintended feature exposure. | Enumerate current route and method grants and require verified email for optional OpenAPI. Assert that an unregistered API path is forbidden and that anonymous and unverified users cannot access OpenAPI. |
| S07 · Medium · Partially mitigated | Build and CI supply chain. The build runs third-party dependencies, images and actions. A malicious or vulnerable artifact can affect CI or shipped releases. CI had persisted checkout credentials and lacks comprehensive SCA, SBOM, secret, IaC and container gates. | Disabled checkout credential persistence, bounded workflow duration, pinned the Maven archive checksum and added an npm advisory gate. Require a reviewed JVM, backend dependency and image inventory, image digests, blocking scans and SBOM publication. Verify findings against actual resolved versions and scanner coverage. |
| S08 · Medium · Open release blocker | Audit integrity and operations. Runtime grants prevent normal audit mutation and tenant attribution is enforced. Privileged database access can still change records, and browser-session revocations are operational log entries. No independent integrity or tamper detection is implemented. | Centralise security events with retention and restricted access. Add signed checkpoints and integrity verification in Phase 4. Verify runtime grant restrictions, same-tenant attribution, checkpoint verification, alert delivery and recovery from backups. |
| S09 · Medium · Open release blocker | Privacy and availability operations. Recovery mail, retention, deletion, correlation and alerting, security monitoring and capacity limits lack end-to-end production evidence. Operational incidents could go undetected or involve excessive retention. | Run registration and recovery mail drills on the selected provider, verify redaction and retention by data class, and exercise rate limits and incident response. Verify production observability from the gateway through the BFF and database. |
| S06 · Low · Remediated in code | Servlet session configuration and revocation API. Cookie-only tracking was implicit, leaving container-dependent URL tracking behaviour, and an already revoked but still resident entry returned success. URL session identifiers, if enabled, may reach logs or history. Management responses could misstate session state. | Explicitly configure cookie-only tracking and make repeated revocation equivalent to an unavailable target. Verify real login, cookie flags and repeat revocation before the target browser makes another request. Check Secure and HSTS at HTTPS ingress before release. |

## Feature security gates

The current tree has no document, billing, background job or regulatory publication runtime. Their risks remain release gates.

| Feature | Verification required before enabling |
|---|---|
| Documents and evidence | Private object storage, server-side tenant and resource checks on upload, share, export and download, quarantine before availability, scanner failures and isolation, URL expiry and revocation. |
| Billing and entitlements | Stripe test-mode signature verification, replay and duplicate event handling, canonical amounts in integer minor units, customer-to-tenant binding, reconciliation, entitlement consistency and cancellation handling. |
| Asynchronous work | Atomic outbox writes, tenant scope revalidation in workers, idempotent retries, recovery from partial failure, dead-letter handling, and cross-tenant queue and export tests. |
| Regulatory rules | Provenance from approved sources, independent review, immutable published versions, historical rule reproducibility, deterministic deadline and applicability boundary tests, and denied unauthorised publication. |

## Verification method and limits

- The initial native database already contained synthetic fixture memberships from earlier work. Flyway upgraded V1 to V2 successfully, but one membership-count assertion failed because those fixtures were present. Repeatable suite evidence uses a fresh database with both migrations and the original assertions.
- Maven verification passed all 8 backend tests on native PostgreSQL 16.14. Flyway applied both migrations to an empty database. The final JAR contains Tomcat core, WebSocket and EL 11.0.29.
- The frozen frontend install passed. All 3 component tests, strict TypeScript checking and the Vite production build passed. Rollup reported the existing Zod annotation warnings.
- All 3 Playwright scenarios passed against the rebuilt Tomcat 11.0.29 API, standalone Keycloak 26.8.2 and native PostgreSQL. They covered OIDC, session cookie attributes, workspace denial, CSRF and owner-only session revocation, including repeat and foreign targets. The local JVM ran with the interim mitigation.
- The npm registry reported no known vulnerabilities for the lockfile via `corepack pnpm audit --audit-level high`. This covers only registry-supplied advisory data. The Java review inventories packaged dependencies and compares selected vendor advisories. It does not substitute for comprehensive backend and container SCA.
- A fresh Maven Wrapper download verified the distribution SHA-256 checked against the SHA-512 published by Maven Central. Compose configuration, Keycloak JSON and workflow YAML parsed successfully. The Docker daemon was unavailable, so the Compose and Testcontainers runtime path remains unverified.
- The Spring Cloud Foundry auto-configuration advisory identifies affected versions before the current Spring Boot 4.1.3. Spring Security’s WebAuthn advisory concerns functionality absent from this BFF. The packaged pgJDBC 42.7.14 incorporates the listed driver fixes reviewed. [Spring Boot advisory](https://spring.io/security/cve-2026-59411/), [Spring Security advisory](https://spring.io/security/cve-2026-59330/), [pgJDBC advisories](https://jdbc.postgresql.org/security/).
